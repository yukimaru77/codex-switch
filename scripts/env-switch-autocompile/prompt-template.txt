/goal このリポジトリは、Codex に追加機能を実装したリポジトリです。追加機能の具体的な内容は、Codex が使用できる組み込み tool に新しいものを実装したというものです。それが env_switch ツールです。

問題意識としては、ssh や docker などの環境で作業をする際、組み込みのほとんどのツールは機能せず、shell を使うしかなかったことです。`docker exec xx` や `ssh xx` のようなことを毎回打たなければいけません。これではトークンの無駄ですし、function output も不安定です。

そこで、これは他の tool の実行先を任意の環境に移すというものです。例えば ssh 先、Docker コンテナの中、またはそのネスト環境など自由です。フックや圧縮後の不整合などで、今いる環境を忘れないような工夫もあります。

`env-switch-v__PREV_VERSION__` と `rust-v__PREV_VERSION__.0` の差分コミットをすべて確認したあと、差分コミットを一つずつ丁寧に `rust-v__VERSION__.0` を起点として、`env-switch-v__VERSION__` に移植を完了させてください。

テスト内容は静的なテストのみでなく、以下の E2E テストも行ってください。

まず初めに cmux で新しいタブを作成します（ワークスペースではなくタブです）。その後、そこでビルドした新しい Codex を `--yolo` で起動し、以下のプロンプトを入力します。

```text
/goal ssh saitou と ssh saitou-h200 に、それぞれサブエージェントを割り当てて、以下のタスクを実行してください。メインのエージェントであるあなたは作業はせず、まとめ役をしてください。

正確に 2 つのサブエージェントを使うこと。

Agent A は ssh saitou をターゲットにする。
Agent B は ssh saitou-h200 をターゲットにする。

各サブエージェントは、SSH ホスト上で一意な名前の GPU 対応 Docker コンテナを作成すること。その後コンテナの内部に入り、PyTorch の CPU 対 GPU 行列積ベンチマークを実行すること。

両方のホストで、CPU と GPU に同じ行列サイズ、ウォームアップ回数、繰り返し回数を使うこと。
```

このプロンプトをそのまま送ってください。これは、いつものような自然なプロンプト（env_switch などの単語は含めない）でも env_switch を自然に選択して使用するか、`/goal` やサブエージェント単位でも機能するかなどの包括的なテストになっています。

これが終わったら、しっかりできているかを確認してください。これが成功するまで `env-switch-v__VERSION__` の改良や移植を続けてください。
